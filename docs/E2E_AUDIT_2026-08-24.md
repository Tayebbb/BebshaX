## 🔴 Blockers

### - [x] B1 — Silent 100 % provenance loss (breaks R3, D8, Phase 6 exit criterion) — FIXED 2026-08-26

`/api/provenance` returns `total: 0` after 4 real LLM calls.

**Root cause, reproduced directly:** [provenance.py](../apps/backend/bebshax/llm/provenance.py) declares `task: str`. `TaskType` is a `StrEnum`, so pydantic coerces it to a plain `str`. But [sink.py](../apps/backend/bebshax/db/sink.py) line 140 does `task=r.task.value` → `AttributeError: 'str' object has no attribute 'value'` on **every single record**.

Direct probe: `record.task = 'PERSONA_GENERATION' type=str` → `written=0 dropped=1 db_errors=1`.

**Why nobody noticed — three compounding defects:**

1. The broad `except Exception` in `_insert_batch` swallows it as if it were a DB outage.
2. The log guard is `if self.total_db_errors % self.log_interval == 0` with `log_interval=100`. First error: `1 % 100 = 1` → **the first 99 failures are completely invisible.** An off-by-one in an error-rate limiter.
3. [test_sink.py](../apps/backend/tests/db/test_sink.py) has 3 tests and **none of them ever calls `_insert_batch`** — they assert `total_written == 0` on a `MagicMock`, which passes for the wrong reason.

**Consequence:** the entire research contribution — routing paths, fallback chains, attempt-level failure data — is thrown away. The routing dashboard can never show anything. Phase 6's exit criterion "every LLM request writes a provenance row" is **not met, and never has been**.

**Fix:** `task=str(r.task)`; log the first error then sample instead of gating on `% 100`; add a round-trip test asserting `total_written == 1`.

> Note: [routes.py](../apps/backend/bebshax/api/routes.py) line 111 already uses the defensive `r.task.value if hasattr(r.task, "value") else str(r.task)` — the correct pattern exists in the codebase, just not in the sink.

### 2026-08-26 — Top-3 QA recommendations implemented and live-verified (Tayeb, owner instruction)

1. **Batch interviews → async job with polling UI.** `POST /studies/{id}/interviews/batch-run` now returns **202 + job_id immediately** and runs interviews in a background task (GC-safe refs, per-persona status registry on `app.state`, last-50 retention); new `GET .../batch-run/{job_id}` polls it, 404 for jobs lost to a restart. ## Methodology & reproduction

- Stack: `docker compose up -d db` (pgvector on 5433) → `uvicorn bebshax.main:app --port 8000` → `npm run dev` (Vite, 5173).
- API probed with a throwaway Python script covering authz, validation and error paths (deleted after the audit; the working tree was left clean).
- UI driven through a real browser: signup → landing → avatar dropdown → Launch Console, with request interception.
- Live LLM journey: create business → generate persona → memories → conversation → 3 turns → transcript → provenance.
- Two false leads were **retracted rather than reported**: a "collapsed button layout" and a "render loop" — both were artefacts of the embedded browser reporting `window.innerHeight === 0`. Setting a real viewport (1440×900) showed correct layout. Always set the viewport before judging layout in that browser.

## Two process notes worth internalising

1. **The mock-fallback pattern (`catch {} → return mock`) converts every backend defect into an invisible one.** It is the direct reason B1, B2 and H1 all survived to now.
2. **A green suite that only exercises fixtures is worse than no suite**, because it manufactures confidence. 142 backend and 8 frontend tests passed while the product was unusable against its own backend.
